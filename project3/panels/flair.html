The brief stops at one collection on one server. A real NoSQL deployment replicates that collection across nodes, and replication brings conflicts. This extra shows them on CROSSFADE's own data.

Why not mimic the replica set in Flask too: a Flask copy of elections and rollback would only show our own model of MongoDB, not MongoDB. Tier 1 therefore drives real servers, and Flask stays out of the data path.

Why not just two nodes

A replica set needs a majority to elect a primary. With two data nodes, losing one leaves 1 of 2, which is not a majority: the survivor stays a secondary and writes stop. The fix is the arbiter from the Unit 12 slides, a voting member that stores no data. So the proposed cluster is two data nodes plus an arbiter, and the “two nodes, no arbiter” failure is shown as a scenario of its own.

Tier 2A peer-to-peer simulator on Flask servers

MongoDB has one primary per replica set, so the multi-primary replication from the Unit 11 slides is simulated, and the simulator follows CouchDB from Unit 12, which is driven entirely over REST. Each node is a Flask server:

  • Nodes. Each Flask server holds its own copy of the tracks documents, seeded from collection.json, and accepts reads and writes. Every document carries a revision (_rev, as in CouchDB) and a vector stamp {a: n, b: m}.
  • Same API as the slides. GET/PUT a document with its _rev, and a _changes feed, so the Unit 12 curl commands work almost unchanged against our nodes. A PUT with a stale _rev is refused: read again, then write.
  • Replication. A background loop on each node pulls the other's _changes. A stamp ahead on every counter wins and is copied with no conflict; stamps ahead on different counters are a conflict: a deterministic winner is kept and the losing revision goes into _conflicts.
  • Merges per field. A stage-name edit on node a and a verified change on node b merge cleanly; two different title edits are flagged for a person.
  • The network is a Flask proxy that all node-to-node traffic goes through. The dashboard can cut it (a partition), add delay or drop a share of requests, then heal it and watch the nodes converge.
  • Testable anywhere. pytest drives several nodes in one process with Flask's test_client, and scripted orderings make each conflict happen the same way every run. No MongoDB or Docker needed.

Ground rules

  • Real Project 1 data only; no invented tracks.
  • Version-stamp and lock fields exist only in the flair, never in collection.json.
  • Every scenario page says whether it runs on real MongoDB (Tier 1) or on the Flask simulator (Tier 2).
  • Every scenario prints progress and node state as it runs, and has its own tests: Tier 1 under @pytest.mark.cluster, skipped when no mongod is available; Tier 2 runs anywhere.
