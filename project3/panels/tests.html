Unit tests

Project 3 · our own QC · planned

The brief doesn't ask for tests; as in Project 2, we add them so every graded file is checked against an answer worked out independently.

Planned. No test is written yet. The layers below are what the suite will cover once the four files exist.

The idea

1 · oraclePlain Python reads the graded data.xlsx and computes every expected answer. No MongoDB involved.
2 · buildmongosh runs collection_creation.js against an empty database on a real mongod.
3 · captureA small shim wraps find and aggregate and records each call's arguments and results as JSON.
4 · comparepytest compares each captured result with the oracle and checks the rubric rules.
5 · plant bugsEach file is broken one way at a time; a test that passed must now fail.

Because the expected answers never come from MongoDB, a failing test points at a real fault: either the migration lost or changed data, or a query is wrong.

What each layer checks

TargetChecks
collection.jsonParses as Extended JSON (bson.json_util). 15 documents. Every column of the 6 tables present at its path with the right BSON type (Decimal128, Date, BinData, boolean). No foreign-key fields remain. Every value equals data.xlsx, decimals at their Project 1 scale.
collection_creation.jsRuns clean in mongosh and produces exactly collection.json. The $jsonSchema validator rejects bad documents (a probability of 1.2, an unknown ingest_status, a missing title). The planned indexes exist.
find_queries.js5–7 commands. Each has a non-empty filter and projection. Rubric letters (a)–(e) each used at least once. Each result matches the oracle: same documents, same projected fields, positional $ returning one array element.
aggregate_pipelines.js5–7 pipelines. Each has at least 2 stages not counting $limit, $skip, $sort. Letters (a)–(e) each used. Each result matches the oracle, Decimal128 averages compared exactly.
All .js filesEvery command is preceded by a comment carrying its test-sync tag (// F2 · UC-…), so the tests and the files can't drift apart.

Planted bugs (mutation checks)

As in Project 2, a script breaks each file in small ways and reruns its tests; a bug counts as caught when a test that passed now fails. Examples:

  • drop one probability from one score, or store a decimal as a double instead of Decimal128;
  • leave artist_id on the track (a foreign key the brief says to drop);
  • turn $elemMatch into two separate conditions, which matches across different array elements;
  • remove the positional $ so the whole scores array comes back;
  • change a $push to $addToSet, or a threshold from $gte to $gt.

Running them

The tests need a real MongoDB: Docker mongo:8, or MongoDB Community Server plus mongosh, with Python and pymongo. The cloud sandbox used to build this site can't download MongoDB, so test runs happen locally. As in Project 2, each file will get a step-by-step PDF for running its tests, and this page will show the latest results.
