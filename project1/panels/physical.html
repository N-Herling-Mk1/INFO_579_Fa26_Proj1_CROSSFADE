Reading it

  • Column icons. A yellow key is a primary key column; a red key is a primary key column that is also a foreign key; a red diamond is a foreign key outside the key; a filled blue diamond is NOT NULL; a hollow diamond may be empty.
  • Lines. Solid lines are identifying relationships: the parent's key is part of the child's primary key, as in all four associative tables. Dashed lines are non-identifying: the foreign key is an ordinary column.
  • Line ends. The symbol next to a table says how many rows of that table relate to one row at the other end. Parents show ||, exactly one. Children show o<, zero or many, because a parent can exist before it has children. Station Blend and Genre Probability show |<, because every station has at least one genre weight and every score has its ten probabilities. The station end of Play's dashed line shows o|, because a play need not come from a station.
  • Indexes. Each table lists its indexes: PRIMARY, one uq_ index per UNIQUE column, and one fk_ index per foreign key that does not already begin the primary key. A foreign key that leads the primary key, such as Track Score's track_id, uses the primary key's index, so it has no index of its own.

How it was built

The diagram is drawn from the requirements analysis, not by hand, so its tables and types cannot drift from the document.

  1. scripts/build_ddl.py reads every table and column from the requirements analysis and writes the MySQL schema: crossfade_schema.sql (with the 16 CHECK constraints), crossfade_workbench.sql (the same without CHECKs, for Workbench), and crossfade_data.sql (all 401 rows of data.xlsx).
  2. The schema and data were loaded into a MySQL-compatible server (MariaDB 10.11): every row loads, and eight deliberately bad inserts, such as a duplicate play or a probability of 1.2, are rejected.
  3. In MySQL Workbench, File → Import → Reverse Engineer MySQL Create Script draws the tables and relationships.
  4. workbench_fixups.py, run from Scripting → Run Workbench Script File, sets what a CREATE script cannot carry: each relationship's participation, box widths so no type is cut off, expanded index lists, and a layout with no line running behind a table.
