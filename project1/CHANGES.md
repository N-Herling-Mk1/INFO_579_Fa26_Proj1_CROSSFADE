## mk4 — reviewer follow-up

- Track Score is no longer called "the only place model output enters the database." It is now "the parent record for every model output."
- The integrity rules no longer rely on the transaction alone.
  - The stored procedures compute derived values themselves and never accept them as input.
  - The application account has EXECUTE on the procedures only, with no direct INSERT, UPDATE or DELETE on Track Score, Genre Probability or Station Blend.
- **I1:** a station must have at least one blend row, created in the same call as the station. The blend is replaced whole on every save.
- **I2:** requires exactly one probability row per Genre record, not only a correct sum.
- **I3:** now covers Model Divergence as a derived value. Divergence depends on the other models' results for the same track, so when any model scores a track, it is recomputed for all of that track's results. (The reviewer did not flag this.)

## mk5 — Model Divergence definition

- **Aggregation defined.** Model Divergence is the mean, over every other result for the same track, of the pairwise base-2 Jensen–Shannon divergence between the two distributions. Each pairwise JSD is in [0, 1], so the mean is too.
- **Single-model case defined.** Divergence is empty (NULL) while only one model has scored the track, because there is nothing to compare against and 0 would claim perfect agreement. The attribute was already Optional = Yes, and the attribute inventory range now reads "0.0000 to 1.0000, or empty."
- **I3 updated** to match: the procedure computes the mean JSD, leaves it NULL with no other result, and recomputes it for all of the track's results whenever any model scores the track.
- **False claim removed.** The description said divergence is "the signal stations filter on," but Station has no divergence bound, only ambiguity bounds on entropy. It now points to the Scoring Model definition, which describes disagreement as a signal.
- **Packaging note.** `Proj1_mk4.zip` was the source-only zip (`requirements_analysis_src_mk4.zip`), which is why it had no PDF or PNG. This package includes the compiled deliverables.

**Generator (`gen_data.py`, seed 579).**
- Probabilities are drawn from each track's intended genre blend, then rounded to four decimals so each result sums to exactly 1.0000.
- Genre ID, Top Probability, Posterior Entropy and Model Divergence are computed from the stored probability rows. Divergence uses the mk5 rule and is blank when only one model has scored the track.
- Before writing, the generator checks:
  - every primary key, UNIQUE column and foreign key, including the composite foreign key from Genre Probability to Track Score
  - integrity rules I1–I6, with the I3 values recomputed independently
  - dates: no score before its model was deployed, no release before the track's first score, and no play before the release, the listener's signup or the station's creation
  - royalties: a play earns the artist's rate only if at least 30 seconds were streamed
  - station plays: a station surfaces only tracks whose entropy is inside its range and whose top genre is in its blend
- The requirements analysis's example values appear exactly in the data. Track 4817 × beardown_3sec gives Top Probability 0.5800, Posterior Entropy 0.4619, Model Divergence 0.0198 and Segment Variance 0.0051, and the example play is a real row.
